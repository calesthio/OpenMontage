# OPENMONTAGE — MASTER ARCHITECTURE & PILOT PLAN V4.1
Дата: 2026-11-06. Основа: AUDIT_1..4 (read-only аудит, kilo/mega-100) + внешний research
+ самокритика/патч по найденным изъянам V4.
Главный принцип всего документа: КАЧЕСТВО ФИНАЛЬНОГО ВИДЕО — приоритет №1.
Любой шаг, который не улучшает то, что видит зритель на экране, — вторичен.

## 0. Что меняется относительно предыдущей версии плана
Раньше Kaggle T4 рассматривался только как резерв для генерации картинок (на случай,
если Flow недоступен). Теперь роль меняется: раз видео НЕ генерируется AI (сборка —
Remotion/ffmpeg, это CPU/браузерный рендер, не GPU-задача), Kaggle T4 освобождается
и переводится на три задачи, которые реально поднимают качество готового ролика:
озвучку, интерполяцию движения, апскейл изображений. Генерация музыки — четвёртая,
опциональная задача при наличии GPU-времени.

## 3. ПОЛНАЯ АРХИТЕКТУРА ПАЙПЛАЙНА (по слоям)

### Слой 0 — Сценарий и раскадровка (CPU, без GPU)
`scene_planner.py` + `script_analyzer.py` превращают текст сценария в JSON-раскадровку:
список сцен, для каждой — текст реплики, визуальное описание кадра, тип движения
камеры, эмоция Stickman. Это ОБЯЗАТЕЛЬНЫЙ отдельный шаг ДО генерации картинок —
по опыту других пайплайнов (storyboard-module), пропуск этого шага и генерация
"картинка на реплику" в лоб — главная причина ощущения "дешёвого AI-слайдшоу".
Сейчас этот код есть, но не используется в проде — ВКЛЮЧИТЬ его в V4.

### Слой 1 — Озвучка (Kaggle T4, GPU)
- Базовый голос: Kokoro-82M (`af_heart`) — быстрый, уже лицензионно чистый (Apache-2.0),
  используется как дефолт и фоллбэк.
- Апгрейд-кандидат на тест: Chatterbox (Resemble AI, MIT-лицензия) — выразительнее,
  с контролем эмоции/темпа, под T4 влезает. Задача агенту: запустить A/B сравнение
  3-4 одинаковых фраз Kokoro vs Chatterbox на T4, оценить разборчивость/естественность,
  решение зафиксировать в STATE-файле (как в прошлых bake-off'ах).
- F5-TTS/Dia/XTTS-v2 — НЕ брать без отдельной проверки лицензии по образцу
  LICENSE_EVIDENCE.md (у части чекпоинтов этих моделей некоммерческие условия).

### Слой 2 — Картинки (Flow как основной источник, Kaggle как фоллбэк)
Без изменений от прошлой версии: Flow/Nano Banana основной (бесплатно по фото),
FLUX.2-klein-4B + SDXL-Lightning фоллбэк на Kaggle. Новый шаг добавлен ПОСЛЕ генерации:

### Слой 2.5 — Апскейл изображений (Kaggle T4, GPU) — НОВОЕ
Проблема из аудита: картинки у Flow/Kaggle часто ниже целевого разрешения и потом
растягиваются наивным resize (это явно отмечено как дефект в QC V1-V3). Решение:
Real-ESRGAN прогоняет каждое изображение перед компоновкой в Remotion. ВАЖНО
(изъян, найденный при ревью V4): не брать anime-модель (`_anime_6B`) по умолчанию —
она тюнится под чёткие аниме-линии и может исказить реальный стиль проекта. Перед
продакшн-использованием сверить 2-3 тестовых картинки с `STYLE_BIBLE.md`, сравнить
anime vs general модель (`RealESRGAN_x4plus`), выбрать по факту. Лицензия Real-ESRGAN
сама по себе открытая (BSD/Apache), но веса конкретной модели проверить так же через
G1-подобный license-check.

### Слой 3 — Сборка и движение (CPU для Remotion + Kaggle T4 для интерполяции) — ГЛАВНОЕ ИЗМЕНЕНИЕ
Это прямой ответ на главную находку аудита: "в V1-V3 внутри сцены нет покадровой
анимации, только статичное наложение + pan/zoom между сценами целиком".
Два уровня анимации, оба нужны одновременно:
1. Remotion (уже есть каркас, Root.tsx, 14 композиций) — программная анимация:
   покадровые keyframe-позы Stickman из stickman_pose_library.py интерполируются
   самим React/Remotion (это бесплатно, CPU, не нужен Kaggle) — закрывает
   "Stickman static pose only" из QC V2/V3.
2. RIFE (MIT) на Kaggle T4 — после рендера Remotion, дополнительный проход
   интерполяции кадров между ключевыми позами фона/персонажа для плавности
   там, где чистой Remotion-анимации недостаточно (например, переходы между
   AI-картинками одной сцены). Это тот инструмент, который реально меняет
   восприятие "слайдшоу" на "видео".
Приоритет: сначала включить честную Remotion-анимацию (это бесплатно и даёт
основной прирост), RIFE — второй проход поверх, если останется GPU-время.
ВАЖНО (изъян, найденный при ревью V4): RIFE создан для интерполяции между кадрами
РЕАЛЬНОГО видео с непрерывным движением. Между двумя разными AI-иллюстрациями без
общего движения он может дать артефакты/"призраки" вместо плавности — это гипотеза,
не проверенный факт. Обязателен тест на 2 сценах с визуальной оценкой человеком ДО
применения ко всему пилоту (см. шаг V4-S7). Если результат плохой — пропустить RIFE
в этой версии, остаться на чистой Remotion-анимации.

### Слой 4 — Музыка (Kaggle T4, опционально, GPU) — НОВОЕ, низкий приоритет
Вместо generic ambient-подложки — Stable Audio Open генерирует оригинальный
трек под хронометраж и настроение сцены. Лицензия — Stability Community License
(тот же порог по выручке, что уже проверялся для SD3.5) — делать только после того,
как Слои 1-3 стабильно работают; это вишенка на торте, не блокер пилота.

### Слой 5 — QC (без изменений, уже сильная часть — 90%)
Полный qc.py (16 проверок) + release_gate.py + illustration_qc.py на каждом билде.

## 4. Пилот V4 — спецификация
- Тема ЗАФИКСИРОВАНА (изъян V4 — тема не была окончательно выбрана): "planet entirely
  without land". Используем существующие наработки V1-V3, не начинаем с нуля.
- Формат: 4–6 минут (не 18).
- Ведущий: Stickman, с реальной покадровой анимацией через Remotion (слой 3.1).
- Картинки: Flow основной источник + Real-ESRGAN апскейл перед сборкой (модель — по
  результату теста против STYLE_BIBLE.md, см. слой 2.5).
- Звук: Kokoro (дефолт) с A/B тестом против Chatterbox на Kaggle.
- Движение: Remotion-анимация обязательна, RIFE — только после успешного теста на
  2 сценах (см. слой 3).
- Музыка: generic подложка для первого пилота — Stable Audio Open только во второй
  итерации, когда база работает.
- Финальный пакет к публикации: видео + миниатюра + заголовок + описание с
  AI-disclosure (синтетический контент) — см. V4-S10.

## 6. Owner-approval точки
- Перед реальным расходом Flow-кредитов (zero_cost_gate).
- Перед использованием любой новой модели (Chatterbox/Stable Audio Open/Real-ESRGAN)
  в проде — после мини license-check по образцу G1, не "на глаз".
- Перед финальной публикацией (release_gate.py).

## 7. Критерий готовности к публикации
Все QC PASS — необходимо, но недостаточно. Обязательно вживую: видно покадровое
движение Stickman (не статичная картинка), нет ощущения слайдшоу, хук в первые
5 секунд, синхронизация эмоции голоса и визуала.

## 8. Мандат агента на самостоятельные находки (добавлено по запросу владельца)
Агент имеет право и обязанность сам искать улучшения, новые инструменты и
проблемы, не предусмотренные в этом плане, по ходу выполнения. Правило: находки
НЕ внедрять самостоятельно, если они необратимы или меняют архитектуру — вместо
этого фиксировать в отдельном файле `docs/V4_AGENT_FINDINGS.md` (что нашёл, почему
это улучшение или проблема, что предлагает), продолжать работу по основному плану,
владелец прочитает и решит, что внедрять. Общее fallback-правило для ЛЮБОГО нового
инструмента в этом плане (Chatterbox, Real-ESRGAN, RIFE, Stable Audio Open и
любого найденного агентом самостоятельно): если не взлетает с одной разумной
попытки — не городить костыли, откатиться на уже рабочий вариант, сообщить
владельцу, продолжать пилот без этого слоя.
