## E1. Целостность озвучки (CPU, высокий приоритет)
Почему: в логе Kokoro было предупреждение "EspeakFallback not enabled.
Out-of-dictionary words will be skipped. espeak not installed". Для
текста про Enceladus, cryovolcanism, hydrothermal такие слова могут
пропускаться или читаться неверно. Неизвестно, затронуло ли это
final.mp4, это нужно проверить, а не предполагать.
1. Поставь espeak-ng (apt-get install -y espeak-ng, при необходимости
   sudo) или добавь явные фонемные переопределения для терминов
   (Enceladus, Europa, cryovolcanism, hydrothermal, subsurface,
   phosphate, Cassini, Juno, Clipper). Проверь, что предупреждение
   исчезло.
2. ASR-проверка "голос против сценария": транскрибируй narration
   локально (faster-whisper small или base на CPU, модель бесплатная),
   сравни с текстом сценария по предложениям, посчитай WER и список
   пропущенных или искажённых слов. Сохрани сырой вывод в qc/raw/.
3. Добавь эту проверку в release_checklist как жёсткий гейт:
   пропущенное слово или WER по предложению > 10% = FAIL, предложение
   перегенерируется (Kokoro, локально).
Критерий: после правки ни одного пропущенного слова, WER по всему
тексту < 5%.

## E2. Ворота "готово" против халтурных рендеров (CPU, высокий приоритет)
Почему: V8 собрался из 7 кадров вместо 41 сцены, длился 140.84 с при
озвучке 169.45 с, и агент всё равно написал "pipeline fully executed".
В release_checklist и в код продвижения рендера в основной файл
добавь жёсткие проверки. Если любая не прошла, рендер не может
стать основным и не может быть назван готовым:
- число визуальных сегментов == число сцен в storyboard;
- |длительность видео - длительность narration_master| <= 1.0 с;
- нет сцен с source = NEEDS_REVIEW в финальном рендере;
- каждый ассет имеет запись в rights_qc;
- средний интервал смены кадра и max_static_segment_sec попадают в
  заданный диапазон или есть записанное художественное обоснование;
- итоговый отчёт агента содержит реальные числа из QC JSON, а не
  пересказ.
Критерий: прогон старого final_v8_experiment.mp4 через новые ворота
должен давать FAIL с понятной причиной. Прогон final.mp4: PASS.

## E3. Бенчмарк image-to-video на бесплатном GPU (Kaggle, средний)
Почему: главная слабость пилота это статичные кадры. Бесплатный 2D
pan/zoom решает это частично. Открытая модель Wan 2.2 (лицензия
Apache 2.0) в варианте TI2V-5B по оценкам влезает в 6-8 ГБ видеопамяти
в FP8, то есть теоретически работает на Kaggle T4/P100 (16 ГБ).
Квота Kaggle по отчётам около 30 GPU-часов в неделю, точное число Kaggle
не публикует, смотри в настройках аккаунта.
Бюджет: не более 2 GPU-часов в сумме. Используй существующий
tools/kaggle_bridge (jobs/), без веб-интерфейса, скриптовым запуском.
Тест: 3 существующих кадра (разрез ледяного спутника, шлейф Энцелада,
подлёдный океан), клипы по 3-4 секунды, 480p, не больше 81-120 кадров
(для T4 это практический потолок по отчётам сообщества). T4 не имеет
аппаратной bf16, используй fp16 или GGUF-квантизацию. Запиши время
на клип, пик видеопамяти, лицензию весов, которые реально скачал.
Критерий принятия: до ~20 минут на клип, нет заметного искажения
научно важных элементов (форма спутника, трещины, шлейф), нет
морфинга и мерцания. Принятые клипы маркируй visual_class =
ARTISTIC_METAPHOR или HYPOTHETICAL_RECONSTRUCTION, они не заменяют
реальный архив и требуют раскрытия AI. Не принято: оставь 2D-движение
motion_director, зафиксируй причину. Использовать не более 5-8 ключевых
сцен, не все 41.

## E4. Разбор чужих репозиториев (read-only, низкий риск)
Цель: взять идеи, не зависимости. Прочитай (git clone во временную
папку вне репозитория, потом удали):
- kajisho5/ffmpeg-skill (MIT): контракт и рецепты FFmpeg, особенно
  работа с таймингами и склейкой;
- официальные Remotion agent skills (npx skills add remotion или
  SKILL.md из репозитория Remotion): правила написания композиций;
- Bomx/super-video-maker-skill: циклы QC раскладки b-roll и финального
  FFmpeg QC (лицензии нет, только читать, ничего не копировать).
Не устанавливай MCP-серверы и сторонние навыки в окружение: это код и
инструкции, которые исполняет агент, доверять без проверки нельзя.
Результат: список из не более 5 конкретных приёмов с обоснованием,
которые стоит перенести в свой код, с оценкой риска. Реализуй только
те, что чинят уже наблюдавшиеся сбои (тайминг A/V, склейка, QC).

## E5. Голос: A/B только при необходимости (низкий приоритет)
Kokoro остаётся основным. Рейтинги TTS Arena показывают Kokoro и
Chatterbox на одном уровне в пределах погрешности, то есть смена
модели сама по себе качество не поднимет. Сделай A/B (Chatterbox Turbo,
MIT, один абзац 60-90 секунд) только если после E1 озвучка остаётся
плоской или с неверными паузами. Оценка по рубрике (разборчивость,
паузы, естественность) плюс ASR WER, результат с обоими файлами для
прослушивания владельцем. Модель не менять без записанного
преимущества.
