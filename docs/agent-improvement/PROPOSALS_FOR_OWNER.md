# PROPOSALS_FOR_OWNER

## Проблема: .git/ занимает 464 МБ, диск на 97%

### Что происходит
Корневой диск раздела `/` (overlay, 32 ГБ) заполнен на 97% (свободно ~966 МБ). Из них `.git/` занимает **464 МБ** — больше, чем весь исходный код репозитория (`lib/` = 1.8 МБ, `scripts/` = 1.1 МБ).

### Причина
Глубокая git-история с множеством коммитов, содержащих бинарные файлы (рендеры, аудио, кадры) и Pack-файлы объектов. История накапливалась на протяжении многих сессий (V6, V7,Factory runs).

### Что нельзя делать без явного согласия
- `git filter-repo`, `git filter-branch`, BFG — необратимо перезаписывают историю
- Агрессивный `git gc --aggressive` — может повредить pack-файлы
- Удаление `.git/` — потеря всей истории и возможности отката

### Варианты решения (требуют вашего решения)

| Вариант | Что делает | Риск | Освобождает |
|---------|-----------|------|-------------|
| `git gc` (обычный) | Перепаковка объектов, удаление unreachable | Низкий | ~10-30% от .git/ |
| `git repack -ad` | Удаление дубликатов объектов | Низкий | ~20-40% |
| shallow clone (`--depth 1`) | Обрезка истории до последнего коммита | Средний (потеря истории) | до 80% от .git/ |
| `git filter-repo` | Удаление больших файлов из всей истории | Высокий (перезапись истории) | переменный |

### Рекомендация
Начать с обычного `git gc` (низкий риск). Если недостаточно — shallow clone на рабочей ветке, сохранив полный клон в бэкапе вне репозитория.

### Связано с
- `projects/pilot/first_video/` (134 МБ, удалено, кроме `final.mp4`)
- `docs/openmontage/slice/` (205 МБ, требует решения отдельно)
- Диск критичен (<5% свободно) — без действий сессия рискует сломаться при следующей записи.
